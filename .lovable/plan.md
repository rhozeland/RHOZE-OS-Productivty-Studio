# Report: Owner instructions on creator tokens / artist coins / pump.fun

This is a research report, not a build plan. No code was changed. Sources: chat history only (message numbers like #1320). "Owner said" lines quote or closely paraphrase the user's messages. "Lovable did" lines come from Lovable's replies in the same chat. Anything I infer is marked **(Inference)**. File and table names come from Lovable's own replies; I did not check them against the code.

Categories: **PROFILE** = coin on a creator profile · **PROJECT/WORK** = coin attached to a project, work, event or space · **DISCOVERY** = charts, chips, lanes, search · **APPROVAL** = token linking, review, verification · **LAUNCHPAD** = in-app coin creation, bonding curve, swaps.

## Reversals and conflicts
- **In-app launchpad (#1218, #1320) → removed.** The #2392 / #2394 pivot replaced it with read-only pump.fun discovery. The redirects were Lovable's own call (memory v10.2).
- **Single profile artist coin (#1494, #1614, #1638) → scrapped in #1640.** Coins became tied to projects, events or spaces. Later (#2394, #2460) there was again one real pump.fun token per profile, which partly brings the profile coin back.
- **Coins on events and spaces (#1234, #1712) → removed in #2038.**
- **"Artist Shares" rename (#1846)** was not kept. **(Inference)**
- **Birdeye price source (#1962, #3320) → Lovable used Jupiter, DexScreener and Birdeye in combination.**
- **Self-serve linking (#2460) → "already have a coin, link it" removed (#3068) → simple CA attach brought back (#3320, #3368).**
- **Coin wrongly shown as attached → owner said only show real attachments (#2713).**
- **Admin approval of tokens** was built by Lovable without an explicit owner request I could find. The owner's team is now questioning it (#3412).
